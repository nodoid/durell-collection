# Building

Needs .NET 10 with the `android` and `ios` workloads, Xcode, Python 3 with Pillow (and py65 for the
translator tools), cc65 for Turbo Esprit.

## The games themselves (not in git)

Nothing taken from the original games is in this repository: no tapes, ROM images or memory
snapshots, and not the translated programs made from them (`src/Durell.Core/Games/*/*.g.cs`, the
embedded `*.snap` and Turbo's `turbo.disk`), nor Lunar Lander's port of the BASIC listing
(`src/Durell.Core/Games/Lunar/LunarProgram.cs`). They are git-ignored. To build the app you need
your own copies:

1. Put the tapes from oric.org and the Oric ROM images in `originals/` (paths are listed at the top of
   `tools/recomp/make_games.sh`), with the coverage logs in `originals/cov/` that the translator uses to
   find code reached only at run time (made by `tools/recomp/explore.sh`).
2. `git submodule update --init` for the Turbo Esprit port, and cc65 to build it.
3. `tools/recomp/make_games.sh` - makes the snapshots and translates all six programs (it reproduces
   the shipped files byte for byte). Star Fighter's Atmos tape image is damaged at `$97F5`; the
   repair is read from the Oric-1 tape (`games.json` "patches").

To find code that random play has not reached yet: `tools/recomp/explore.sh harrier 30000 --random 3`.

## Releases

`build/build-release.sh [all|android|ios|macos|windows]` -> `releases/`. Personal settings come from
`signing/local.properties` and `signing/apple.props` (templates in `build/*.example`); the Android
upload key is made once with `build/create-android-keystore.sh`. Provisioning profiles `devel-durell`,
`rel-durell`, `devel-durell-mac`, `rel-durell-mac` must be installed.

## Android versions

The app supports Android 12 (API 31) and later (`SupportedOSPlatformVersion` in
`src/Durell.Android/Durell.Android.csproj`) and targets the latest API, 37 (`android:targetSdkVersion` in
`src/Durell.Android/AndroidManifest.xml`; keep both `uses-sdk` values in step). The .NET 10 Android
workload binds API 36, so the build warns `XA1008` until a workload with API 37 bindings is installed;
then raise the `TargetFramework` to match (e.g. `net10.0-android37.0`) and the warning goes.

## Testing on an iPhone

Current iOS stops apps that don't use the scene lifecycle, at launch (`_UIApplicationEvaluateRuntimeIssueForNoSceneLifecycleAdoption`);
the app adopts it (`UIApplicationSceneManifest` in `Info.plist`, `SceneDelegate` in `src/Durell.iOS/Program.cs`, which
puts MonoGame's window into the scene). The simulator does not enforce this, so test on a device:

```bash
DEV=$(python3 -c "import re;print(re.search(r'<DurellAppleDevIdentity>(.*?)</',open('signing/apple.props').read()).group(1))")
dotnet build src/Durell.iOS -c Release -p:RuntimeIdentifier=ios-arm64 -p:CodesignKey="$DEV" -p:CodesignProvision=devel-durell
xcrun devicectl list devices
xcrun devicectl device install app --device <UDID> src/Durell.iOS/bin/Release/net10.0-ios/ios-arm64/DurellCollection.app
xcrun devicectl device process launch --device <UDID> --console uk.co.allthejohnsons.durellcollection
```

To see the screen without a screenshot tool, copy a file `selfshot.txt` holding times in seconds (e.g. `6,12`) to the
app's `Documents` (`xcrun devicectl device copy to ... --domain-type appDataContainer --domain-identifier
uk.co.allthejohnsons.durellcollection`): the app then saves `selfshot-N.png` and a start-up log `diag.txt` there to copy
back. An empty `selfshot.txt` turns this off. Crash reports: `xcrun devicectl device copy from --domain-type systemCrashLogs`.

## Checking every key

`dotnet tools/Durell.Capture/bin/Release/net10.0/Durell.Capture.dll LOOK OUTDIR --script keycheck` plays
every game live in the real app, in both looks, pressing each of its keys through the same path a
player's keypress takes, and checks the game itself reacted (its memory changed as that key should
change it); results in `OUTDIR/keycheck.txt`. Desktop looks (`mac`, `windows`) press keyboard keys and
check a redefined key; phone and tablet looks (`iphone`, `ipad`, `android-phone`, `android-tablet`) use
tilt, touches on the picture (fire) and the on-screen buttons. Latest: 82/82 keyboard, 54/54 per touch layout.
